# 阶段 E：流式 JSONPath、标量过滤与查询结果分页

日期：2026-10-16。基线：0.7.6 / `f21db89`。按用户明确要求以 0.7.7 收录本阶段（本次版本提交），Cargo 两文件及项目文档同步。仅核对源码差异、版本文本和暂存文件列表；未运行测试、构建、Clippy、格式检查或基准，不将提交授权写为实测通过；S0 继续暂停。

## 1. 已实现的入口与职责

| 模块／入口 | 本次行为 |
| --- | --- |
| `engine/query/syntax.rs` | 独立词法／类型化语法层：路径步骤、选择器、标量过滤 AST；同时保留现有库的 JSONPath 合法性校验 |
| `engine/query/predicate.rs` | 存在性、类型保持的标量比较、逻辑组合、根／当前节点单路径访问、十进制数比较 |
| `engine/query/stream.rs`、`QueryEngine::run` | 独立 Query Input／Event API，Memory／Indexed／Sparse Provider，按节点向下一步传递，不收集中间命中向量 |
| `query_stream_worker.rs` | 默认 GUI 的生产线程和有界读取线程；结果页／复制在后台处理，最新状态用单槽共享句柄合并 |
| 公共 ResultStore／ResultCursor | 查询按序写入、保留重复项；新增只取节点的游标和有限祖先前缀复用，避免值输出逐条重建完整祖先链 |
| `export::Selection::Stored` | 完整结果或固定部分前缀的流式值复制／导出；会话检查和取消；不从截断预览生成完整输出 |
| 主 CLI `--query`／`--get` | 使用新执行器和磁盘结果；完成后输出，`--get` 仍要求恰好一个结果 |
| `sparse_index --query` | 稀疏后端的独立 CLI 入口，输出完整结果数组；一般 JSONPath 尚未接入分页树 GUI 的查询面板 |

文本搜索继续使用自己的引擎、匹配器、状态和取消代次；本阶段没有把 JSONPath 过滤转换为常规搜索。

本地核对 `serde_json_path` 0.7.2 的公开接口及源码后，确认其 JsonPath 包装内部 Query，没有公开提取 AST 的入口。因此没有依赖私有字段、unsafe 或库源码补丁，也没有新增依赖。本次新增词法／语法层，不将之前 Indexed 的字符串切分解析器冒充完整 RFC 执行器。

## 2. 支持范围

新流式入口支持：根 `$`、字段名、转义引号键、数组下标及负下标、通配符、联合选择、正反向切片、递归选择。联合及重叠递归不去重，输入顺序和重复选择均保留。`[::0]` 选择零个节点。

文件后端的过滤子集：

- `@.field`／`@['field']`／`@[index]` 等单路径存在性。
- 当前节点 `@` 和根 `$` 的字段／数组下标路径，可用于跨字段、根阈值比较。
- 字符串、JSON 数字、true、false、null 字面量。
- `== != < <= > >=`、`!`、`&&`、`||` 和括号；逻辑组合短路。

示例（示例表达式，不是本次执行结果）：

```text
$.rows[?@.active].name
$.rows[?(@.amount >= 100 && @.region == 'CN')].id
$.rows[?(@.amount >= $.minimum || !@.optional)].id
$.rows[3,0,3].id
$..items[::-1]
```

存在性按“是否选中节点”判断，值为 false／null 仍是存在。缺失与 null 不等，两个缺失单路径相等；不对字符串和数字做隐式转换。数字按符号、有效数字和十进制数量级比较，不转换为 f64，不展开巨大指数所代表的零串。指数超出 i128 范围或运算溢出明确报错，不能声称覆盖任意长度的指数。

文件后端暂不支持函数、过滤操作数中的通配符／递归／多节点路径，以及数组／对象的深度比较。容器存在性可以使用，但容器比较会明确失败；若此前已有命中，结果标记为失败的部分结果，不自动全量物化为 Value。

## 3. Memory 兼容路径与旧 API

Memory 的普通选择器使用新管线；过滤及新解析器不支持、但原库认可的高级表达式保留现有库路径。该路径仍会构造完整库结果／NodeIds，库求值内部不可中断；之后才逐条写入 ResultStore。不能据此宣称所有 Memory JSONPath 都是有界或即时首条返回。能力矩阵中的 Memory 取消／增量标记按这个最坏路径描述。

D 阶段的 `Document::query_path`、`QueryEngine::execute/document`、CompiledQuery 和内部收集适配保留原 NodeIds 契约及 Indexed 原语法子集；E 功能通过 `QueryEngine::run`、默认 GUI、主 CLI 和 Sparse 查询 example 使用。不要用旧收集接口的测试或旧“不支持过滤”断言作为新入口通过／失败的结论。后续接口收口需明确统一或淘汰兼容入口，而不是静默更改原返回类型。

新入口也接受以 `/` 开头的 Pointer。完整索引的无效／缺失 Pointer 仍产生零结果；独立 SparseIndex.pointer 保留 D 的严格错误、空 Pointer 根和 16 KiB 约束。Sparse 的新查询入口与旧 Pointer API 是两个明确入口，不将其行为混同。

## 4. 执行、导航与资源边界

每个选中节点立即执行后续步骤，递归选择使用显式遍历栈；没有“先完成一整段通配符结果，再执行下一段”的中间数组。首条最终命中立即发布，后续 128 条一批；约每 100 ms 的访问检查也会发布未满批的结果，结束时发布剩余部分。进度是执行访问次数，可能重复访问同一节点，不是唯一节点数或准确扫描百分比。

Provider 新增按名称定位和顺序子节点访问：Sparse 复用磁盘字段目录，Legacy 数组用直接下标，Legacy 对象顺序遍历复用前一子节点结束位置。Legacy 对象确定字段的结果序号仍可能需要扫描对象直属子节点，根引用／宽对象查询可能产生明显额外成本，未做性能测量。

结果分页继续使用共享内存／磁盘账本和有限热页，不能把文件结果换成另一份常驻大 Vec。祖先前缀复用只复用定位记录，不合并结果序号。输出和复制可以继续持有旧任务的明确结果快照；新任务、清空、文件切换按代次丢弃迟到页和剪贴板内容。

明确保留以下资源约束：

- 源文件需要完整验证。未完成的 Sparse 会话返回 Pending，不把当前已发现数量当作完整数组长度；渐进加载期间的自动等待／恢复不属于本阶段。
- 查询步骤最多 128，树路径深度最多 127；过滤嵌套／逻辑运算有显式有界工作区检查。
- 文件过滤每个标量序列化／解码输入最多 256 KiB；大标量返回资源错误，不静默作为“不匹配”。根输出／普通选择器不受此标量过滤上限限制。
- Sparse 名称查找沿用 16 KiB 键命令限制。
- 解析／AST／遍历使用共享预算中的保守工作区预留；库分配、allocator 和整个进程 RSS 仍不能声称被精确硬限制。
- 磁盘配额不足或中途读取／求值错误停止生产并保留明确部分状态。没有总命中条数固定上限，也没有恢复旧 256 MiB 结果 ID 固定上限。

## 5. 默认 GUI 与输出

查询生产和结果页／剪贴板读取使用两个固定有界通道，分别保留最新请求和容量 1 的完成消息；批次消息不携带节点数组，UI 状态合并为一个结果句柄。绘制只使用内存状态和已返回页，不读取结果磁盘。

- JSONPath 结果区每页 16 条，前／后页按结果序号读取，显示已发布总数和页区间；总数完成前为下界。
- 首次结果定位一次，之后普通选中不会被新批次反复抢回。切换结果页可定位该页首条，保留顺序和重复项。
- 新查询立即移除旧查询结果；取消保留当前已提交部分，Clear 清除查询。失败时允许显示已完成页和错误，不冒充完整结果。
- Copy all／Export all 只用于完成结果；Copy partial／Export partial 捕获点击时已发布前缀。部分导出文件名为 query-partial.json。
- 剪贴板仍有 8 MiB 默认提示；超过时用户可选后台继续复制或导出，沿用共享预算。复制和完整导出都使用磁盘游标，不复制当前 16 条页冒充全部结果。
- 预览仍有既有输出截断，完整结果不会从预览字符串恢复。新游标输出的空白／缩进可能与旧整份序列化不同，结果顺序、数量与 JSON 值保持契约。

分页树 GUI／S4 回退 GUI 尚无一般 JSONPath 查询面板，属于后续 UI 收口；本次未宣称这些界面已接入。Sparse 引擎有可调用 API 和 CLI 入口。

