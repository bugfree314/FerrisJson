### A 的适用限制

后一个顶层键位于前一个值之后，扫描器仍必须读过前一个值才能发现它。因此巨大首值可以先显示其键及类型，但其后兄弟键仍需等待扫描，不能承诺所有顶层键瞬时到齐。

交接前下级展开、检索和完整 JSON 复制/导出不可用；对象或数组预览是占位，标量/字符串仅取有限片段，选中预览最多读取 16 KiB。名称最多保存 640 UTF-8 字节、行标签最多 160 字符；被截断名称不提供不完整的复制路径。单个键的原始编码超过 64 KiB、嵌套超过发现上限 128 或目录超限时停止可选发现，原完整加载仍继续并决定文件是否合法。重复顶层键可暂时按源顺序出现，最终保持原后端既有的最后值语义。

A 保留完整 DOM/完整文件索引及其最终可见行构造，完整加载成本、最终交接卡顿风险尚在。两个阶段并行读取也可能争用 I/O；Low memory load 等待旧文档释放仍可能推迟发现启动。没有把发现预算当作全应用内存保证。粘贴、标准输入、非 Windows 平台和实验分页界面不改为本次默认发现路径。

## B：后台递归与按需展开（待实施）

1. 将发现目录升级为可定位父子关系及值范围的持续索引，替换 A 的完整加载交接。
2. 后台以顺序扫描为主，减少随机 I/O；优先服务用户展开/选中的容器。不要对全文件做需要保存完整边界队列的纯 BFS，也不要让深层 DFS 阻塞已选节点。
3. 下级完成一页即可用，节点身份与会话隔离；换文件、取消、失败均退休旧任务，避免迟到结果污染。
4. 保留原 UI，只把树和预览的数据来源替换为有界页；后台索引动作不绘制到前端。
5. 验证巨大首值、宽对象、深嵌套、快速展开/换文件、资源释放和最终语义，不以已发现数量冒充完整总数。

## 验证与测量入口

```powershell
cargo test --offline --locked --all-targets
cargo clippy --offline --locked --all-targets -- -D warnings
cargo fmt --all -- --check
cargo build --offline --locked --release --bin FerrisJson --example top_level_bench
target/release/examples/top_level_bench.exe FILE
target/release/examples/top_level_bench.exe FILE --indexed
```
