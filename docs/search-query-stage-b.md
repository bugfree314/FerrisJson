## 已实现的边界

| 文件 | 职责 |
| --- | --- |
| `src/task_worker.rs` | 泛型 TaskWorker<W>，只处理有界调度、会话／任务代次、取消、预算预留和完成消息；不分支判断 Search／Query |
| `src/search_worker.rs` | 默认 GUI 的 SearchRequest／SearchWorker 兼容适配，以及原有分页树 SearchHub；文本匹配仍使用 S6 引擎 |
| `src/query_worker.rs` | 独立 QueryRequest、QueryOutput、QueryWorker，包装现有 Document 查询与预览 |
| `src/app.rs` | 分别提交与接收强类型结果，独立搜索／查询耗时及结果错误；没有混合结果的 unreachable 分支 |
| `src/main.rs` | 注册新模块，移除旧 worker 模块 |

旧 `src/worker.rs` 已由公共调度模块及两个专用适配器取代，Operation／Output 混合枚举移除。SearchWorker 和 QueryWorker 是不同的泛型实例，分别持有线程、待办槽、容量 1 完成通道、会话标识与取消代次。公共调度代码复用不意味着两类操作共享运行队列。

调度沿用旧约束：新请求替换本类任务；结果发送前释放 Document；满通道可取消；poll 同时检查会话及任务代次；关闭时唤醒等待线程。请求及结果保留期间的预算预留继续保留。

SearchRequest 复用 S6 的 Query 数据结构，因此默认 GUI 和分页树不会各自定义一套文本搜索选项。默认 GUI 的 SearchWorker 仍使用 Document 的完整 NodeIds 兼容收集器；分页树 SearchHub 继续使用磁盘 ResultStore，没有把默认界面改为显示分页结果。

## UI 状态变化

- 原 query_duration 拆成 search_duration 和 path_duration；搜索输入变化只重置搜索耗时，查询执行／清空只重置查询耗时，切换文档重置两者。
- 底部可同时显示 Search 与 Path 耗时，完成顺序不再决定另一操作的耗时是否消失。提示说明预览可能异步完成，不将其冒充计时内已完成。
- JSONPath 成功不再清除通用加载／输出错误；查询错误仍只存在对应结果中，搜索错误沿用独立 search_error。
- 搜索提交因预算等原因失败时清除待显示的搜索高亮，避免没有有效任务却残留高亮。
- 原有结果列表、n/N、JSONPath 首条定位、预览及导出语义保持在兼容适配层中。
