## 1. 现状与需要改变的部分

| 当前证据 | 对大文件的影响 | 对应阶段 |
| --- | --- | --- |
| `src/app.rs::load_file` 默认按 Indexed files 设置选择后端，默认关闭；内存后端 `read_to_string` 后构造完整 Value | 未选择索引模式时仍承担整份文本和 DOM 成本 | S1、S8 |
| `src/indexed.rs::open` 先复制整份快照，再严格扫描，结束后一次返回 Document | 首次可浏览时间依赖完整复制和扫描 | S2、S4 |
| `Document` 保留完整 nodes/children/keys；Indexed 另保留每节点 Range | 不构造 DOM 仍随节点数线性增长，不能自然覆盖 10 GB 密集小节点文件 | S1、S3 |
| `Viewer::poll` 为每个节点创建 expanded；初始 `depth < 2` 会展开根及其直属容器 | 顶层巨型数组可能在首屏准备时生成大量逻辑行 | S5 |
| `visible_into` 两次遍历可见结构并生成完整行数组；展开、定位触发 `rebuild_rows` | `show_rows` 只减少绘制，行数据和重建仍可能很大 | S5 |
| `Viewer::select` 同步调用 preview/path；绘制中的 row cache miss 同步调用 `row_preview` | 随机文件读取、解码和格式化可能阻塞 UI | S2、S5 |
| `Snapshot::read` 用 Mutex + seek/read_exact | 并行读取串行化；收益和锁等待需要单独测量 | S2 |
| Worker 已有代次取消和容量 1 的完成通道，但 Search/Query 返回整份 NodeIds | 有界消息个数不等于有界结果字节数；首条结果需等任务完成 | S6 |
| Indexed 查询每步构造结果 Vec；过滤和函数明确不支持 | 大通配符结果有中间数组重叠；高级查询需另建执行路径 | S6、S7 |

已完成的基础应继续复用：28 B 节点、共享键、u32 编号、文件快照、严格扫描、限量子树解析、LRU、取消及过期结果丢弃、流式导出、超大复制提示、默认手动检索。不要将这些重新列为新成果。

历史 300 MiB / 21,409,599 节点对照：Indexed 加载后工作集约 985.18 MiB，峰值约 1,516.45 MiB，加载约 5,569.41 ms；内存模式约 5,411.26 ms，未测出打开加速。该数据来自 0.5.0 开发期间的 **0.4.3 工作区二进制**、文档引擎三次中位数，不是 0.5.1 GUI 或新方案成绩。不能按文件字节数线性外推；见优化记录第 17 节。

## 2. 分享建议的采纳与调整

采纳：增量扫描、L1 稀疏检查点 + L2 按需目录、持久结构索引、统一预算、任务优先级、分页结果、可取消执行器。数组检查点同时按元素数和扫描字节数设阈值，必须位于合法边界。

调整以下内容后实施：

- **沿用 egui**：分页和虚拟树是数据模型问题，迁移 Tauri/React 不作为性能重构前置条件。
- **分块随机读取先行**：先完成 FileSource 抽象；mmap 仅作为后续实验，不能将映射原文件时的时间戳检查视为安全保证。
- **快照和快速首屏分开处理**：稳定快照模式继续保留；另提供明确标识的直接读取会话，才能避免首屏等待完整复制。直接读取对并发原地修改不能提供绝对快照一致性；发生变化时失效重开，不混用两个文件代次。
- **首屏不等于有效文档**：首屏可以显示根类型、已发现的前若干子节点及“正在校验”；未闭合的容器没有确定 end 或总元素数。全文校验结束前，不显示“已完整加载”。
- **搜索语义保持兼容**：现有搜索按解码键/值匹配，不能用原始字节搜索替换它；原文搜索如后续增加，应为独立选项。
- **FTS 示例需要重做验证**：分享中的 `content=''` 表配合 `content LIKE ...` 不能直接作为实施方案。SQLite 官方说明 contentless 表除 rowid 外返回 NULL，且 detail=none 对 MATCH 有限制。阶段 S8 应验证候选检索和原文复核的完整链路。参考 [SQLite FTS5 官方文档](https://www.sqlite.org/fts5.html#external_content_and_contentless_tables)。

## 3. 目标模块与接口

先拆为单仓库 Rust 模块和 `src/lib.rs`，让 GUI、CLI、基准共用引擎；有稳定边界后再决定是否拆 workspace crates。建议职责：

| 模块 | 职责 |
| --- | --- |
| `engine/source` | 文件身份、会话代次、read_at、快照、变化失效 |
| `engine/scanner` | 可恢复词法/结构状态、严格校验、安全边界、扫描进度 |
| `engine/index` | 稀疏容器/数组检查点、对象字段页、块读写及持久化 |
| `engine/navigator` | 子节点分页、路径定位、祖先解析、小子树按需访问 |
| `engine/query`、`engine/search` | 查询规划、流式过滤/匹配、顺序和兼容性 |
| `engine/tasks`、`engine/budget` | 取消、调度、有界消息、内存与磁盘配额 |
| `tree_model` | 虚拟范围节点、展开状态、逻辑行定位、有限页缓存 |

拟定公共接口（设计草案）：

```text
open(source, consistency_mode) -> Session + OpenEvents
children(session, node_ref, cursor, limit) -> ChildPage
preview(session, node_ref, byte_limit, cancel) -> Preview
locate(session, path, cancel) -> NodeRef | Pending | Error
search/query(session, expression) -> TaskId + ResultEvents
result_page(task, cursor, limit) -> ResultPage
export(task_or_selection, destination, cancel) -> ExportEvents
```

NodeRef 使用会话/文件代次 + u64 偏移或持久逻辑地址，不依赖完整前序数组编号；偏移仍需由同一版本的结构扫描器确认。现有 u32 ID 在旧后端适配层保留。范围行是 UI 导航项，不冒充 JSON 值；复制路径和导出必须指向实际节点。

未知状态显式表达：范围 end 可未发现，child_count 可未知，页游标可 Pending，结果总数在完成前是下界。任务事件区分 Batch、Progress、Complete、Cancelled、Error；批次包含会话代次、任务代次、序号及扫描覆盖范围。结果页游标保持查询顺序和重复项，不强行去重。

## 4. 分步实施顺序

每阶段单独形成可审查变更；通过阶段门槛后才继续迁移依赖方。阶段编号不是发布版本号。

### S0 — 建立可解释的基准与正确性基线（P0）

范围：扩展 `examples/memory_bench.rs` 和 `scripts/measure-memory.ps1`；已有基准入口继续使用，不重新从零建设。增加 Indexed 的展开、搜索、查询、切换、导出场景，另加 GUI 帧时间与任务排队采样。

记录首次可交互、首个有效子节点页、完整校验、索引就绪的四个时间；细分复制/读取、扫描、重复键处理、索引写入、初始树页和预览。记录工作集、private/commit、索引容量、缓存字节、结果存储字节、磁盘读写、锁等待及取消延迟。工作集与应用堆分开报告。

数据：小文件、已有 300 MiB 历史输入、新专项 100/300/500 MB；结构覆盖密集小节点数组、巨大单字符串、宽且键名唯一的对象、深嵌套、重复键、转义、多语种、大整数，以及尾部错误/截断。逐级执行，预算或磁盘不足时记为失败/未测，不能补造结果。真实用户文件单独记录，不纳入仓库。

验收：旧两个后端在可共同支持的表达式上结果一致；报告有真实提交/包版本、硬件、输入哈希与结构、样本数量和缓存口径。耗时/内存至少三次给中位数与范围；GUI 和查询延迟的 P95 用足够多交互样本，不用三次测量冒充稳定分位数。冷缓存只有实际控制后才标注，其余记录 OS 缓存未控制。

回退：只增加观测入口，基线功能不变。完成后能定位“打开慢”属于复制、扫描、结构分配还是 UI 接管。

### S2 — 文件访问和可取消后台任务（P0）

实施状态（2026-10-13）：基于 0.5.2 / `63b709a`，0.6.0 已实现偏移读取、分级 I/O 准入、可取消等待、独立后台选中/行预览、有界请求/消息和关闭时的导出清理。保留受控快照和既有 Reader/子树缓存，不新增直接原文件读取、共享块缓存或 mmap。75 项自动测试和严格 Clippy 通过；GUI 实机与跨平台功能验收未完成。详见 [S2 优化记录](performance-optimization.md#21-s2--定位读取与可取消后台预览)。S0 被用户明确暂停，本阶段不执行其观测和基准。

范围：把 Snapshot 的 Mutex + seek 读取拆为 FileSource，评估平台定位读取（Unix read_at、Windows seek_read）及有界块缓存。保留受控快照；直接读取只使用文件句柄和拷贝到有界缓冲区的数据，变化失效规则覆盖原地修改、截断、替换及身份变化。

任务优先级：交互页/选中预览 > 用户搜索/查询 > 后台索引/预取。浏览预览不与耗时全文任务共用不可抢占的单一执行队列；同时限制全局 I/O 并发，避免为每个点击无限生成线程。

验收：并行搜索时滚动/选择可响应；文件变化不使用旧范围读取新文件；取消发生在读取、锁等待、满队列和清理路径都能终止。基准比较读取吞吐和锁等待，不能仅凭去锁宣称加速。

回退：FileSource 可继续采用旧快照读取实现；直接读取模式可关闭。

### S3 — 固定内存扫描与稀疏索引 CLI 原型（P0，核心架构门槛）

实施状态（2026-10-14）：基于 0.6.0 / `db863ac`，0.6.1 新增独立 `sparse_index` example。显式栈严格扫描，容器、数组检查点与对象字段目录落盘；数组标量无常驻逐节点索引，对象重复键保留首次位置及最后值。按用户更新的验收范围，以固定 1 MiB 受管理内存预算完成两种结构的 50/100/500 MB 扫描及首/中/末定位，14 项新增测试与旧后端对照通过。上述样本验收执行时包版本为 0.6.0 工作区。尚未迁移 GUI，不表示所有平台或性能目标已验收；详见 [S3 优化记录](performance-optimization.md#22-s3--固定内存扫描与稀疏索引-cli-原型)。

范围：先实现不依赖 GUI 的扫描/导航原型。重用现有 UTF-8、数字、转义和错误规则，扫描状态改为显式栈，按深度预算保护；不能简单搜索逗号或括号。扫描只保存活跃容器状态并逐块落盘，不保留每个标量的常驻 Node/Range。

L1：根/重要容器及数组检查点；初始实验参数为最多 1024 个元素或约 1–4 MiB 到下一个合法边界。字节阈值不是单个巨型元素的扫描硬上限。容器目录即使条目很多也分页落盘，不将“所有容器”换一种形式驻留内存。

L2：按访问建立有限子树节点目录；大量唯一键不进入无限共享键表。巨型对象字段目录分页/磁盘存储。重复键保留旧语义：首个键位置、最后值；不得先展示首个值后声称最终正确。可先顺序完成对象扫描，再发布已定稿字段页；宽对象的临时去重表应有预算及落盘路径。

索引草案：显式小端编码，包含 magic、格式/扫描器/语义版本、源身份、状态、提交序号；按块组织容器、数组检查点、对象字段页及可淘汰 L2。块有长度、范围检查、校验和；记录 u64 字节偏移和元素序号。禁止直接转储 Rust 结构体内存。尚未确定编码大小，必须以实测容量报告。

验收（按用户 2026-10-13 更新）：CLI 在固定受管理内存预算下扫描 **50 MB，再逐级至 500 MB**，本次分级为 **50 → 100 → 500 MB**（MB = 1,000,000 字节）；定位数组首/中/末元素并对可解析样本与旧后端核对。超长单值、多唯一键、极宽/深结构、重复键和跨块错误均覆盖。任意不可支持的结构须有明确资源错误，不能 OOM 或静默错值。该调整仅适用于 S3；S0 保持暂停，其他阶段的原始大文件目标不改写为已完成。

回退：原型单独开关，不替换默认后端。**该门槛未通过，不启动整个 GUI 的新索引迁移。**

### S4 — 渐进打开、持久缓存与恢复（P0/P1）

实施状态（2026-10-14）：0.6.2 / `139c540` 工作区已实现 Session 事件、数组安全首批页、尾部失败状态、两代不可变检查点、解析栈恢复、严格全源字节比较与独立 `--sparse` 有限 GUI 浏览。107 项自动测试、严格 Clippy、Windows Release 主程序/example 构建和 9 项 CLI 边界检查通过；两种约 50 MB 数组三轮新建/复用/异常退出恢复通过。仅稳定快照/严格复用；首次成本包括两次快照复制，检查点复制完整索引，恢复/复用会完整检查磁盘索引。GUI 实机、其他平台、真实断电/磁盘满及 1–10 GB 未验收；完整分页树仍属 S5。详见 [S4 实施与专项记录](performance-optimization.md#24-s4--渐进打开持久缓存与恢复工作区实现)。实现阶段测试/测量版本保持 0.6.2，本次同步文档并提交为 0.7.0，创建本地 0.7.0 tag，不推送。

范围：接入 Session 事件，根元信息/已完成页先交付，完整验证继续后台运行；以 committed frontier 标注安全发布边界。末尾非法 JSON 必须从 validating 转 failed，使查询/导出不能继续将该会话当作有效完整文档。

负索引、反向切片、完整子节点计数等依赖容器结束/长度的操作显示 Pending 并可取消，不能用已扫描数冒充总数。对象页定稿受重复键处理约束。首屏遇到巨大单值或尚无可完成子节点时展示概要和进度，不承诺任意文件都能立即显示真实数据页。

持久缓存：`manifest.bin`、结构块、检查点/字段块及构建状态；临时写入 + 校验 + 提交记录，只发布完整块。恢复保存结构边界及父栈/元素序号，或退回最近安全边界重扫；单一字节偏移不能作为恢复依据。检验源版本后才能恢复或复用。

文件身份、大小/时间和头尾采样可快速筛选，但不能证明全文件内容一致。强校验会产生完整读取成本；快速复用和严格复用分开记录策略与适用条件。稳定快照模式计入复制和磁盘配额；直接读取模式的并发修改限制必须在 UI/README 中说明。缓存格式错误、磁盘不足和异常退出均应回退为安全重建或明确失败。

验收：分别测首次首屏、完整验证、索引复用和恢复；原地改写/替换/截断不能误复用；部分文件、损坏缓存和中途取消不能显示已完成。断电恢复、磁盘满及缓存版本不兼容有回归覆盖。

回退：关闭缓存或渐进模式，继续完整验证后交付；稳定快照后端保留。

### S5 — 真正分页的树与异步预览（P0）

实施状态（2026-10-14）：基于 0.7.0 / `46b149c` 实施，本次版本提交为 0.7.1，历史专项测量仍为 0.7.0。Provider 适配三个后端，磁盘 AVL 序号/权重目录与展开例外，64 行窗口及有限节点页缓存；逻辑全展开与整数行定位不生成全量 UI 行。三个固定后台线程交付不可变安全页、交互帧和独立输出；预览布局有缓存。新树采用 `--sparse`，S4 回退为 `--sparse-pages`，旧后端可用 `--paged-tree [--indexed]`。搜索仅提供引用定位桥接，稀疏搜索/一般 JSONPath 待 S6/S7。专项与剩余边界见 [S5 记录](performance-optimization.md#25-s5--分页树与异步预览工作区)，原生 GUI/GPU 和跨平台不因 headless 检查而标为完成。

范围：将 expanded 全节点数组改为有限展开集合/策略，将完整 rows Vec 改为分页或分段树模型；巨大数组和对象使用虚拟区间，页内加载实际节点。展开/折叠只修改受影响区段；滚动请求视口及有限预取，不为了得到总行数枚举全部节点。

避免把数千万元素变成数万范围行后再一次驻留；区间也要按需生成。全展开改为逻辑展开策略，按用户视口加载，不创建所有叶子行。保持 hjkl、gg/G、数字跳转、搜索定位和历史；未知总行数时明确显示状态，G/负索引可等待计数完成。大逻辑行数需验证 egui 的浮点滚动精度，可通过区间导航和局部滚动窗口处理。

preview/path/row label 异步请求并缓存；布局缓存按内容代次、主题、宽度和 Wrap 失效。分析 `json_preview` 分词/排版调用频率后优化，不把重复布局列为已测根因。概要截断与完整复制/导出保持独立语义。

验收：100/300/500 MB 巨型数组的初始页、展开、折叠和滚动不创建与全部节点数同阶的 UI 数据；树内存受页预算限制。同时检索/建索引时记录 GUI 帧时间，确认导航、范围节点和实际 JSON 路径正确。

回退：两个旧后端继续走公共分页 API；保留旧树实现用于小文件对照，实验配置可切回。

### S6 — 增量搜索、有界结果存储与背压（P0）

实施状态（2026-10-15）：基于 0.7.1 / `47fa5ff` 完成实现与自动验证，本次提交为 0.7.2；历史专项测量保持 0.7.1 工作区版本。统一 Matcher 和前序流式遍历适配三个后端，首条立即/后续 128 条批次、4 事件背压；临时磁盘命中/祖先记录、8×128 热页和 16 条 UI 页，固定搜索线程与三个已有线程共存。输入框、Live、防抖、计数 n/N、Ready 等待、新查询取消、完整/部分游标导出已接入。旧兼容收集器限制 65,536 命中，不再使用全键布尔数组。文件 Regex 每个键/字符串/数字原文范围限制 256 KiB，其他语义和预算错误显式处理。

专项默认 100/300/500 MB，标量/嵌套各三轮，低命中 3 条，高命中每个数组元素的 payload/string 一条；百万命中另有自动回归。实际验证和未验收边界见性能记录第 26 节。S0 不恢复，原生 GUI/跨平台不因 headless 检查而视为验收。

范围：Search 从 `Result<Vec<u32>>` 改为批次事件 + 有界 ResultStore。初始实验批次 100–200 条、通道 4–8 批，同时约束消息字节；路径和预览延迟生成，不在每条命中上持有完整字符串。

结果页采用内存热页 + 临时磁盘顺序追加；UI 只保留有限页。结果存储达到磁盘配额时显式暂停/终止并标注部分结果，不能静默丢失。`n/N`、数字计数跳转和搜索定位通过 ResultStore 查询；扫描未完成时总数为“至少 N”，未找到下一条可以等待继续扫描。

保留解码键/值、大小写、Unicode、正则及顺序规则；覆盖跨块转义和任意长值。正则无法在固定工作内存下支持的情形继续明确限制，不无提示换语义。旧内存后端扫描也通过同一结果接口，不能只把巨大 Vec 拆成消息后声称流式执行。

导出所有结果使用结果存储游标；未完成任务可选择等待完整结果或明确导出已完成部分，UI 不能把部分输出命名为完整结果。单向检索直接导出可考虑执行器写入临时输出；分页历史仍须有受控存储。

验收：首次命中无需等待全扫描；全匹配下内存保持预算、磁盘用量可解释，前端变慢时背压有效；取消满队列、清空、新检索、切换和导出不会应用旧批次或漏/重排结果。

回退：旧整份结果接口仅保留受预算的小文件路径；大文件超限须明确拒绝，不能默默恢复无界累积。

### S7 — JSONPath 流式执行与过滤（P1）

范围：将 Indexed 的字符串选择器执行改为有类型的查询计划和游标，先迁移已支持的 Pointer、字段、索引、通配符、递归、联合选择、切片，再增加明确列出的过滤语法。AST 是否可复用现有库公开接口需实施时核实；不可复用时另实现受测试覆盖的解析层，不使用临时字符串切分逐步冒充完整 RFC。

执行策略：字段/确定下标走目录和检查点；通配符与递归流式访问；过滤先读取必需字段，避免整条超大记录物化。中间结果用迭代器或受控外部存储，支持负索引/反向切片所需的长度等待和反向页访问。

明确过滤、函数、类型比较、大整数、缺失/null、存在性、根 `$`/当前 `@` 引用的能力矩阵；顺序和重复选择维持旧语义。跨记录/根引用可能需额外访问和多遍扫描，应记录成本。未支持表达式继续明确错误。内存后端保留旧库完整功能；不自动把文件后端全量物化为 Value。

验收：支持子集与旧后端逐项对照，包含顺序/重复/零结果、反向切片、Unicode 键、精度、类型和过滤；百万命中不产生百万大小的中间内存数组。长求值可取消，并使用 S6 的分页存储/导出。

回退：保留已有语法子集；新增过滤功能按能力开关发布，未实现部分持续明确报错。

### S8 — 按实测优化、默认策略与发布验收（P1–P3）

先分析 CPU/I/O/内存 profile，分别试验读取块大小、预取、mmap（受保护快照或可证明稳定的输入）、SIMD 局部解析、表达式缓存及有限并行扫描。每个实验都计入初始化、转换和额外空间；未获得可重复收益不替换稳定实现。

频繁重复检索才评估 SQLite FTS5/字段索引。候选索引必须与搜索的解码、大小写和 Unicode 语义兼容，候选集不可漏掉真实匹配；原始文本分段不能自动覆盖 `\\uXXXX` 解码后的语义搜索。短词、正则、跨段、超长查询和大小写差异须有扫描回退及最终复核。先验证官方接口与最小实验，不能照搬分享中的 contentless/LIKE SQL；索引磁盘配额是限制，不是体积预测。

默认策略按 S0–S7 结果决定：优先让大文件进入新文件后端，但文件字节数之外还看节点密度、预算和一致性模式。手动覆盖保留；不能在资源不足时自动转回完整 DOM。发布前验证 GUI 文件对话框、长键滚动、连续切换、关闭/取消、复制提示及多结果导出，再执行各平台验收。

验收：每个优化有同输入前后数据和语义检查；自动策略有可解释条件，失败行为可恢复。大文件能力与平台支持只标注实际完成的矩阵，不因 Windows 通过就宣称全平台 10 GB 已验收。

回退：数据库/mmap/SIMD 保留独立开关；稳定分块扫描与稀疏导航继续可用。

## 5. 初始预算与性能验收口径

以下都是**待验证的工程目标**。以本地 64 位桌面、目标 SSD 和指定数据结构为口径；不能把分享中的“10 GB 首屏 ≤1 秒”当作当前成绩或任意文件保证。

| 受管理核心内存分组 | 初始预算草案 |
| --- | ---: |
| 文件扫描/读取缓冲 | 32 MiB |
| 稀疏索引热页及目录 | 48 MiB |
| 节点/子树缓存 | 32 MiB |
| 搜索及解码工作区 | 32 MiB |
| 查询状态/中间工作区 | 32 MiB |
| UI 数据页、结果热页和消息队列 | 32 MiB |
| 元数据及暂存预留 | 48 MiB |
| 合计 | 256 MiB |

这是全局共享预算草案，不能每个任务各拿一份。GPU/字体/egui 内部、allocator 元数据、未纳入的分配与映射驻留页另测；超预算首先淘汰/背压/落盘，其次返回明确资源错误。调度器限制旧新会话重叠。不能将 256 MiB 定义为总进程 RSS 上限。

| 指标 | 初始目标 / 验收方法 |
| --- | --- |
| 快速首屏 | 典型数组在直接读取或可信缓存会话下争取 ≤1 秒；单列首个有效页。快照模式计入复制，不共用该承诺 |
| 完整校验/索引 | 记录总耗时、扫描吞吐、磁盘读写；不设通用毫秒目标 |
| 已索引页展开 | 热缓存 P95 ≤50 ms；冷缓存另列 |
| 已索引路径定位 | 热缓存 P95 ≤100 ms；未建目录/容器未闭合另列 |
| GUI 滚动 | 目标 60 FPS；记录 CPU 帧时间 P50/P95/最大值及长帧，不仅平均 FPS |
| 取消 | 普通文件 I/O 下争取 P95 ≤200 ms；阻塞系统调用/关闭清理另报 |
| 搜索/查询 | 首批延迟、完整扫描时间、重复执行 P50/P95、候选索引命中率及建索引成本分开 |
| 内存/磁盘 | 256 MiB 受管理核心预算；进程峰值/稳定工作集和 commit、临时快照/结果/索引空间分别报告 |

首次扫描和强身份校验仍随字节数增长；未索引的递归/过滤/全文搜索仍可能遍历全文件。稀疏检查点省的是常驻索引，不能消除跨过单个巨大元素的读取成本。
