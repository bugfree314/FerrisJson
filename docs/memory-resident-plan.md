## M1：已验收并提交的基础层

- Store 新增内存构造入口，使用固定容量 4096 条的记录块及内存哈希桶；ID 采用与原后端兼容的虚拟偏移，增长不复制既有记录块。
- 子目录 AVL、可见行权重、源偏移目录及重复键登记链可复用原记录操作，避免额外实现另一套排序/重复键语义。M1 不修改递归会话的默认构造入口，默认路径接入在 M2。

- 原 UI、文件打开、搜索和导出保持当前默认路径；M1 可验收范围是基础代码、构建产物及既有功能人工回归，不宣称已有交互加速。

## 后续阶段边界

M2 将原递归会话的节点/子目录/源位置与展开排名切换到内存，继续只交付可见页面，不生成整树可见行数组。M3 将磁盘命中记录和有效排名改为内存，保留代次隔离、重复键撤回及最终顺序；预览、完整复制与导出仍读取受保护源，并保留原限制与原子导出。M4 依据可说明的分配成本完善内存预算和超限提示，不在未测量时宣称 RSS 上限或统一速度收益。

内存占用随节点和命中数量增长；密集小节点文件可能远比同大小的巨型字符串消耗更多结构内存。扫描、解码、目录维护与锁竞争仍有开销，原文中部/尾部命中仍需读过前面的数据。内存不足时明确失败，自动迁移到磁盘后端不属于首轮四阶段范围。

## M4：当前交付与人工验收

基于 M3 / `56a4a47`。默认 Windows 文件入口继续采用“原文按需读取，节点/命中驻留内存”，不新增后台面板或模式开关。原文件名增加悬停说明，显示该会话受管理内存用量、峰值和上限；只读取内存预算账本，不读取源文件或调用系统内存采样。

### 预算配置

默认 512 MiB；启动前设置 FERRISJSON_MEMORY_MIB，可配置 64–32768 MiB。未设置使用默认；非整数、空值、越界或非 Unicode 值明确报错，不静默截断。读取发生在打开文件时，每个活动会话固定其上限；外部改变环境变量不会更新已启动程序，需重新启动。

```powershell
# 在自己的 PowerShell 中设置，再启动要验收的程序：
$env:FERRISJSON_MEMORY_MIB='1024'
& .\target\release\FerrisJson.exe
# 恢复默认：关闭程序，在该 PowerShell 中移除变量后重新启动：
Remove-Item Env:FERRISJSON_MEMORY_MIB
```

本阶段未执行以上启动命令或环境变量回归。下限 64 MiB 用于保留会话/匹配器/页面等固定工作区空间，上限 32768 MiB 是可配置范围边界，不代表机器具备该容量。512 MiB 是默认政策值，不是本轮测量得出的通用最佳值，也不是预分配量、系统可用 RAM 或 RSS 上限。

分块记录、哈希桶、块目录和工作区共用原预算账本；扩容前先预留，失败返回错误。预算超限显示 MiB 请求总量/上限并提示以较大配置重新启动或减少节点/命中；真正的分配失败提示释放系统内存或改用较小预算，不把物理内存不足误报为预算太小。其他既有后端仍沿用原预算与错误形式。

### 占用说明（布局推导，未经本轮实测）

| 结构 | 基础布局 | 限制 |
| --- | --- | --- |
| Record | 12 个 u64，共 96 字节 | 一条 JSON 节点可能对应多条索引/目录记录 |
| 记录块 | 4096 条容量，共 384 KiB | 按块分配，末块可能未用满，另有块目录开销 |
| Store 哈希桶 | 65536 个 u64，共 512 KiB | 节点与每个命中 Store 各自持有桶；未使用的桶也占空间 |
| 一条搜索命中 | 命中 Record + AVL Record，基础 192 字节 | 不含桶、末块空余、分配器及旧引用/重建开销 |
| 会话/队列 | 原有 24 MiB 保守账本预留 | 属于预算预留，不等于实分配或 RSS |

不从源文件大小推算结构总量。重复键的旧子树记录保留到会话释放，撤销命中仍保留存储记录；旧结果引用和最终语义重建可增加峰值。文件数、字体/GUI、线程栈、分配器和操作系统缓存等也影响进程/系统内存。M4 不增加自动磁盘回退、动态系统内存策略、后台 RSS 监控或数据压缩。

## M1–M4 之后：动态百分比预算（0.8.9）

2026-10-16，用户要求“动态限制内存为系统总内存的 25%（默认），用户可设置，设置菜单在 help 右侧”。基于 0.8.8 / `526a738` 实施；用户认可并要求提交后收录为 0.8.9（本次版本提交）。以下 0.8.8 构建与待验收表述保留为实施时记录。

- 默认比例 25%，菜单滑条为 1–100%，位置紧随 Help。Settings 中修改草稿比例后 Apply 保存并应用，Reset to 25% 恢复草稿默认，再点 Apply 生效。
- 通过 Windows GlobalMemoryStatusEx 读取总物理内存 ullTotalPhys，预算字节数为 floor(总量 × 百分比 / 100)。计算使用 u128 中间值并检查平台 usize 范围，不沿用固定 64 MiB 下限或 32 GiB 上限。
- 原 ColorSettings 设置文件新增 memory_percent，旧配置缺字段使用 25%；非法比例拒绝读取。内存比例与其他设置一起保存，恢复配色不重置它；旧 FERRISJSON_MEMORY_MIB 不再生效。
- 打开文件时即使用保存比例；当前界面每 5 秒刷新系统总量和预算，Apply 立即尝试。预算调整在统一账本锁内进行，既有分配不会被强制驱逐。
- 若降低到当前占用以下，当前上限保持原值，保存比例仍用于后续文件；菜单提示释放内存或重新打开后应用，后续 5 秒刷新继续重试。不会把“已保存比例”误显示为“当前实际上限已降低”。若之后继续分配超过实际预算，仍沿用明确的超限错误。
- 菜单显示系统总量、所选比例对应预算、当前受管理用量/实际上限；文件名悬停仍显示用量/峰值，并指向 Settings 配置。预算不是进程 RSS 或当前可用 RAM，多个会话退休重叠、GUI/字体/线程栈等不由单个会话预算完整覆盖。
