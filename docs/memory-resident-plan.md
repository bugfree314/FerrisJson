## M1：已验收并提交的基础层

- Store 新增内存构造入口，使用固定容量 4096 条的记录块及内存哈希桶；ID 采用与原后端兼容的虚拟偏移，增长不复制既有记录块。
- 子目录 AVL、可见行权重、源偏移目录及重复键登记链可复用原记录操作，避免额外实现另一套排序/重复键语义。M1 不修改递归会话的默认构造入口，默认路径接入在 M2。
- Record 为 12 个 u64，键和值保留源偏移；内存结构不保存整文件原文或完整 DOM。原记录/目录等价性未经本轮运行测试验证。
- 固定记录块、块目录和哈希桶的分配均计入原预算机制；分配失败或超限返回错误。内存后端不创建索引临时文件，文件视图、持久化、磁盘缓存和回滚事务入口明确拒绝。
- 原 UI、文件打开、搜索和导出保持当前默认路径；M1 可验收范围是基础代码、构建产物及既有功能人工回归，不宣称已有交互加速。

## 后续阶段边界

M2 将原递归会话的节点/子目录/源位置与展开排名切换到内存，继续只交付可见页面，不生成整树可见行数组。M3 将磁盘命中记录和有效排名改为内存，保留代次隔离、重复键撤回及最终顺序；预览、完整复制与导出仍读取受保护源，并保留原限制与原子导出。M4 依据可说明的分配成本完善内存预算和超限提示，不在未测量时宣称 RSS 上限或统一速度收益。

内存占用随节点和命中数量增长；密集小节点文件可能远比同大小的巨型字符串消耗更多结构内存。扫描、解码、目录维护与锁竞争仍有开销，原文中部/尾部命中仍需读过前面的数据。内存不足时明确失败，自动迁移到磁盘后端不属于首轮四阶段范围。
