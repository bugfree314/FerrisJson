# 搜索与 JSONPath 分离：阶段 C 实施记录

日期：2026-10-16。基线：阶段 B 提交 `bf5f69d`，包版本 0.7.4。C 按用户要求收录为 0.7.5（本次版本提交）；按用户要求未运行测试、构建、Clippy、格式检查或基准。用户于本轮明确要求提交，未提供新增实测通过记录，S0 继续暂停。

## 1. 公共结果存储

`src/engine/search/results.rs` 提取为 `src/engine/results.rs`，搜索模块保留原公共类型的再导出，现有分页树、example 和库调用方无需同时改完导入路径。

| API／模块 | 职责与约束 |
| --- | --- |
| ResultStore／ResultWriter | 延续临时磁盘顺序追加、校验和、共享预算及有限热页；不负责匹配、查询表达式或高亮 |
| `ResultStore::session`、`node` | 核对源会话；只读取结果节点，不为普通导航构造完整祖先链 |
| `ResultStore::page` | 最多 128 条的有预算结果页，返回发布时的计数／状态快照；页大小是单页限制，不是总结果数限制 |
| `ResultWriter::selection` | 按 Location 追加一个选择，保留顺序与重复项；跨会话和超深祖先链明确报错 |
| ResultCursor | 固定已提交前缀的顺序游标；完整结果要求任务完成，部分结果必须明确给出前缀；不重新收集完整节点数组 |
| `engine/results/output.rs` | 共用 Provider、游标和原子输出，支持值／完整路径、完整／部分输出；搜索 output 模块保留兼容入口 |

结果存储仍保留节点与祖先记录两种物理记录，供分页树定位复用；祖先路径不是搜索匹配信息。搜索继续复用已记录祖先，查询未来可通过 selection 追加任意结果序列，不要求排序，也不强制去重。只在默认 GUI 的搜索适配层使用按节点 ID 有序的假设。

Writer 只接受一次终态 finish，结束后拒绝追加。生产者未 finish 就退出时标记取消，避免完整输出等待永不结束；仅已发布记录可读。显式取消、预算耗尽或语义错误仍保留部分结果状态，不将其标为完成。临时文件随最后引用释放，导出可以继续持有其明确选择的旧结果快照。

## 2. 默认 GUI 接入 SearchHub

新增 `src/legacy_search.rs` 作为现有完整索引界面的适配器，旧 SearchWorker 的 NodeIds 收集适配已移除。Memory 和 Indexed 的默认 GUI 现在与分页树共用 SearchHub／S6 执行器。

```text
搜索请求 → SearchHub → S6 遍历 → 公共 ResultStore
                                  ↓
当前视口／目标序号 → 独立后台读取通道 → 节点定位、视口命中页
                                  ↓
                             UI 内存快照
```

- UI 保存结果存储句柄、当前序号及当前视口的命中信息，数量从已发布状态读取，不创建完整命中 NodeIds。
- 视口请求和命中页使用带预算的共享引用；只保存实际绘制视口的节点，不引入总命中数上限，也不把超过某一单页大小的可见行静默丢掉。
- 结果磁盘查找在独立有界 TaskWorker 中执行，I/O 优先级为 Interactive；生产扫描保持 Background。绘制只读取已返回的页，不在行绘制中读取磁盘。
- 每个默认 GUI 只有一个搜索生产线程和一个结果读取通道；新视口替换待办，已有请求／完成消息仍有界。重复查询不会按命中数创建线程。
- 首次定位保持原搜索起点与方向：正向找起点后第一条，反向找起点前最后一条；需扫描范围足够或完成后才能决定的目标保持等待。完整结果可循环，失败／取消的部分结果不冒充完整集合循环。
- n/N 及数字计数通过结果序号导航；新目标取消旧目标读取。会话、搜索任务代次和视口修订共同过滤迟到数据。
- 明确取消搜索保留已提交部分结果，可继续浏览／导出；清空、新搜索及文件切换清除旧视图。修复 SearchHub 发布事件／错误时取得锁后没有再次核对取消代次的窗口。

现有无 GUI 的内部调用改用同步磁盘结果适配，仍不创建完整命中数组；实际绘制界面的搜索与结果读取均走后台。它不是新增主 CLI 的流式接口。

## 3. 用户可见变化

- 搜索状态和导航移到可换行的独立一行，避免新增按钮挤压搜索输入。
- 扫描中显示 `at least N`；完成才显示准确总数。Cancelled／Failed 明确标记 partial。计数是已发布命中数，不是准确扫描百分比。
- 新增 Cancel search，保留部分结果；Clear 继续清除搜索状态。
- 新增 Export matches 菜单：All values、All paths 仅在完成后可用；Partial values／paths 捕获点击时已发布前缀，文件名明确带 partial。
- 输出继续通过后台原子临时文件替换，沿用取消导出和关闭时的清理；跨会话结果拒绝输出。
- 搜索高亮根据后台返回的视口命中信息显示，新视口或新批次到达时可能短暂等待页返回。JSONPath 结果区与搜索状态仍独立。

## 4. 保留的边界

本阶段没有把 JSONPath 结果接入公共 Writer；查询请求和现有 NodeIds 适配仍留给 D，新的流式查询、过滤属于 E。主 CLI 的 Document 搜索兼容接口仍完整收集结果；默认 GUI 和分页树已使用磁盘结果。默认 GUI 的树索引、展开标记和可见行数组仍是旧结构，本阶段只迁移搜索结果，不能声称整个界面已经固定内存。

磁盘结果带来额外临时磁盘与读取成本，小文件未必更快；没有测量数据支持性能提升。热页沿用 8×128 条，公共输出仍预留既有路径工作区；这些是代码参数，不是 RSS 或实测内存上限。共享预算、单值 Regex、搜索词长度、输出路径限制继续保留。资源不足要明确失败，解除旧固定结果上限不表示无限资源。
