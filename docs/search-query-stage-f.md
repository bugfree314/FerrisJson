# 阶段 F：分页树查询入口与兼容边界收口

日期：2026-10-16。基线：0.7.7 / `b730729`。按用户明确要求以 0.7.8 收录 F（本次版本提交），Cargo 两文件及项目文档同步。本次仅核对源码差异、版本文本与暂存文件列表，未新增或运行测试，未运行构建、Clippy、格式检查、GUI 验证或基准；不将提交授权或源码核对写为功能验收通过。S0 继续暂停。

## 1. 分页树 GUI

`--sparse`、`--paged-tree` 和 `--paged-tree --indexed` 增加独立的 JSONPath 输入、Run query 与结果区。原 Path 栏仍执行单 JSON Pointer 导航，`.` 仍聚焦 Path；JSONPath 输入按 Enter 或 Run query 执行，不随普通搜索的 Live 设置自动运行。

- 查询结果按 16 条一页后台读取，显示表达式、完成／部分状态、已提交数量和查询耗时。点击具体结果时定位树节点，普通批次到达不会自动改变选中项。
- Cancel query 保留已提交部分结果；Clear query 清除请求、结果页和状态。新查询替换旧请求，搜索和查询分别拥有取消代次，互不清除结果。
- 完整复制／导出要求查询完成；部分复制／导出固定点击时已发布前缀。预览按路径 512 字节、值 160 字节的既有接口生成，完整输出从节点游标读取，保留顺序和重复项。
- 分页树查询复制沿用该界面的 8 MiB 硬边界，超过时明确提示使用导出；没有新增“继续超大复制”弹窗。默认旧树 GUI 仍保留 E 的 8 MiB 提示后继续复制行为。
- 查询页读取错误在结果区显示，提供 Retry page；翻页或重跑可以重新请求。错误不改变整个查询任务的完整／部分状态。
- 文件打开和重载沿用先退休旧 Task 再打开新会话。迟到页和复制内容按查询代次过滤；结果输出额外验证源会话。

`--sparse-pages` 保留为旧有限页浏览器，没有加入第二套查询执行器或查询面板，界面说明明确指向 `--sparse`。该入口的历史用途仍保留。

## 2. 调度与资源生命周期

新增 `paged_query_worker::QueryHub`，使用独立生产线程、一个最新待执行请求、一个待运行输入槽和一个共享结果状态句柄。事件不携带节点数组，不随结果数量积累 UI 消息。请求和表达式展示预算通过共享 Reservation 跟随请求／快照保留。

查询通过 Provider.query_input 捕获独立只读输入。Sparse 在完整源验证前保留最新请求并显示等待状态；Ready 后由交互线程派发。验证失败清除待执行查询并取消生产；文件切换、取消和退出唤醒等待线程，线程加入既有异步退休与退出回收。

生产通道独立于普通搜索，页读取与树导航共用既有 Interactive 通道，输出共用既有单任务输出通道，通道忙时明确报错。交互请求队列仍最多 16 项，结果页保留最新请求；导航和搜索切换保留查询页／唤醒请求及已排队的输出，避免丢失请求后界面一直等待。

复制在后台读取，清空／重跑后丢弃迟到剪贴板内容。已捕获的导出持有旧结果快照，可在新查询开始后继续完成；全会话取消／重载仍取消输出。捕获前被新查询淘汰的输出请求报取消，并释放输出忙状态。

查询值输出复用公共 results/output::write_values，以 next_node 游标读取，避免逐条解码祖先。公共值导出也走此路线，不再为仅导出值预留原先路径导出的 64 MiB 工作区；路径导出保留原处理。该实现调整尚未测量，不报告加速或 RSS 降幅。

## 3. 新旧 API 的明确范围

| 入口 | 契约 |
| --- | --- |
| QueryEngine::run | 新执行语义；Provider 输入、磁盘结果、流式状态，文件后端使用 E 的标量过滤子集 |
| QueryEngine::collect | 显式需要完整 NodeIds 的新接口；先执行 run，再用游标收集，结果及数组容量仍受预算保护 |
| 默认 GUI、主 CLI、分页树 GUI、Sparse CLI | 使用新执行入口；默认 GUI 无 Worker 的同步兼容路径也改用新 collect 语义 |
| query::compatibility::collect／CompiledQuery | 显式保留 D 的完整收集及 Indexed 语法契约；兼容能力矩阵单独提供，不以新入口能力冒充旧入口能力 |
| QueryEngine::execute/document/find、根级 CompiledQuery 别名、Document 旧查询方法 | 保留源码兼容，文档标明旧契约，内部转入 compatibility；未静默改变返回类型或旧 Indexed 过滤错误 |

旧 QueryRequest 对 TaskWorker 的完整收集适配只留在现有测试构建中，生产 GUI 使用流式 Worker。没有删除历史用例，也没有将它们的原断言写成新入口的验证结果。

这次收口保留明确的兼容边界，没有声称删除所有旧解析代码。Memory 的高级语法／过滤仍使用原库完整结果和不可内部取消的调用；文件后端不新增函数、容器比较或多节点过滤操作数。

## 4. 验证状态与剩余限制

本次只阅读源码和差异、核对调度、取消、版本和文档；未执行任何测试／构建／GUI 或性能命令。以下均待用户验收：

- [ ] 三种分页树后端的 Run query、零结果、多页、重复选择、Unicode、标量过滤、错误和结果点击定位。
- [ ] 验证中多次更换查询后只执行最新请求，取消等待、验证失败／重载无旧结果出现。
- [ ] 搜索和查询同时运行、分别取消，连续导航／翻页不丢结果页请求，队列满时可重试。
- [ ] 完整与部分复制／导出的数量、顺序、值、固定前缀；超过 8 MiB 的复制错误与大结果导出。
- [ ] 复制中重跑／清空无旧剪贴板，已捕获导出继续完成，文件重载／退出能回收生产与输出。
- [ ] 页读取失败及 Retry page、输出捕获失败后通道恢复、预算不足与磁盘故障处理。
- [ ] 新 run／collect 与显式 compatibility 的能力、语法及旧调用契约分别核对。
- [ ] 大文件专项仍为十进制 100／300／500 MB 的低／高命中；记录实际二进制版本、样本和缓存口径，不挪用历史成绩。

默认旧 GUI 的完整结构索引／可见行数组、Memory 库内不可取消、查询深度和单标量工作区等 E 限制继续保留。分页树查询与树导航共用读取通道，不能据此保证任意磁盘或复杂查询下的交互延迟；预算不是总进程 RSS 上限。无新增性能数据，所有样本／测试 JSON 和基准 JSON 报告不纳入提交。
